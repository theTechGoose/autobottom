# Notes on the data

- Fails come from `GET /admin/failed-audits/findings` filtered on department `DS MB`, shift `PM`, and the question header. Appeal and judge state comes from reading each finding doc with `GET /audit/finding?id=<findingId>`.
- **Dateleg ID** is the QuickBase record ID of the date leg. All 101 findings here are date-leg audits (none are package audits), so every row has one.
- **The appeal comment is per-appeal, not per-question.** Someone appealing several questions at once writes one comment covering all of them, stored once on the finding. So a comment may be arguing a different question than the section it appears under — `onhxkOiWwSLE3Za8jQW48` appears in both sections with the same comment. The judge note is written per question and always refers to the question it is listed under.
- A blank comment means nothing was typed. The box is optional and is only saved when the person writes something (`src/audit/domain/business/file-appeal/mod.ts:115`).
- The appeal record stores who filed it (`auditor`), but no HTTP route reads appeal records, so the filer name is not shown. The team member on the audit is shown instead.
